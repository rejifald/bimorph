---
title: 'Contextual codecs'
description: 'Add a Ctx type parameter so decode and encode require the runtime context a value cannot carry, checked at compile time.'
---

Make a codec contextual when its conversion needs a runtime value the wire and
domain values don't carry — a region to parse a phone number, a locale to read a
currency symbol, the exponent to scale a stored minor-unit amount. The `ctx` is a
third type parameter, and the type won't let you forget it.

## Example

```ts twoslash
import { iso } from 'bimorph';

// wire stores minor units (cents); the domain wants major units — but how many
// decimal places to shift depends on the currency, which only the context knows.
const Amount = iso<number, number, { exponent: number }>({
    decode: (minor, ctx) => minor / 10 ** ctx.exponent,
    encode: (major, ctx) => Math.round(major * 10 ** ctx.exponent),
});

const price = Amount.decode(1999, { exponent: 2 });
//    ^?
```

Forget the context and it's a compile error, not a runtime one:

```ts twoslash
// @errors: 2554
import { iso } from 'bimorph';

// [!code fold:start]
const Amount = iso<number, number, { exponent: number }>({
    decode: (minor, ctx) => minor / 10 ** ctx.exponent,
    encode: (major, ctx) => Math.round(major * 10 ** ctx.exponent),
});
// [!code fold:end]
Amount.decode(1999); // the { exponent } context is required
```

<Callout type="info">
    Resolving a *discrete code* against a table from context — an id against a
    directory, a country code against a glossary — is common enough to have its own
    combinator. Reach for [`Directory`](/docs/guides/context/directory) rather than a
    hand-rolled `iso` with `.find()`: it inverts the table for `encode` and makes a
    miss loud instead of returning `undefined` cast to your domain type.
</Callout>

## Options

Add the context as the third type parameter to any leaf constructor and a `ctx`
argument to `decode` and `encode`. Every door then requires the trailing `ctx`:
`decode(b)` stops compiling and `decode(b, ctx)` is required.

Two rules make context composable:

- **`Ctx` must be an object type** — `{ region: string }`, never a bare `string`.
  Composition merges child contexts by intersection, which only works on objects, so
  keep field names meaningful and disjoint (`region`, `locale`, `exponent`).
- **Supply it per call, or bind it once.** Pass `ctx` per call when it varies;
  [`.bind(ctx)`](/docs/guides/context/bind) fixes it for a batch and hands back an
  ordinary context-free codec.

<Callout type="warn">
    **Anti-pattern:** don't type `Ctx` as a bare primitive like `string`. Two codecs
    that both need a `string` would collide when composed, and the intersection
    `string & string` tells you nothing. An object with a named field — `{ region:
    string }` — merges cleanly and documents what the value is.
</Callout>
