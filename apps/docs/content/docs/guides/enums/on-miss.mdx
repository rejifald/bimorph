---
title: 'default & recover'
description: 'Recover an unmapped wire value with a static default or a resolver — and how omitting both keeps the decode input a closed union that rejects a miss at compile time.'
---

When a wire value falls outside the map, an `Enum` has two recovery slots — a static
`default` value, or a `recover` resolver — and, if you set neither, it stays strict:
the decode input is the **closed union** of declared wires, so an unmapped value is a
_compile_ error, not a runtime one.

## Example

```ts twoslash
import { Enum } from 'bimorph';

// A `default` keeps decode total: an unmapped wire falls back instead of throwing.
const Status = Enum([[1, 'active'], [0, 'inactive']], {
    default: 'inactive',
});

const label = Status.decode(9);
//    ^?
```

## The choices

| You write | Decode input | An unmapped wire |
| --- | --- | --- |
| _(neither slot)_ | closed union (`0 \| 1`) | **compile error** |
| `recover: 'throw'` | widened (`number`) | throws at runtime |
| `recover: (c) => …` | widened (`number`) | runs the resolver |
| `default: value` | widened (`number`) | returns `value` |

Both `default` and `recover` **widen the decode input** from the closed union of
declared wires to the wire's primitive base — recovery only makes sense for values
outside the map. Omitting both keeps the union closed, which is why an unmapped
literal won't even compile.

`recover` is the dynamic slot: a resolver that receives the input (and any context)
and returns the domain value, or calls `raise()` to fail with the standard error.
Its `"throw"` shorthand is sugar for `(c) => c.raise()` — accept the wide input, but
re-raise on a miss.

```ts twoslash
import { Enum } from 'bimorph';

const Status = Enum([[1, 'active'], [0, 'inactive']], {
    recover: (c): 'active' | 'inactive' => (c.input > 1 ? 'active' : c.raise()),
});
```

The [resolver](/docs/guides/recovery/resolver) is the primitive `recover` is built on,
and the `default` value is just its most common shorthand.

<Callout type="warn">
    **Anti-pattern:** don't use `recover` to pattern-match spellings you already
    know — `"new-search"`, `"newSearchUI"`. Those are exact, so they're
    [aliases](/docs/guides/enums/aliases): typed, narrowed, and visible in the
    declaration. A resolver is for genuinely computed recovery.
</Callout>
