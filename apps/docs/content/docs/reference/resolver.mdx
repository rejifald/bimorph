The types behind recovery: the resolver function, the context it receives, and the
`reconcile` presets that desugar to it. The
[resolver guide](/docs/guides/recovery/resolver) shows them in use.

## ResolveContext

What a resolver receives to recover a failed mapping — or re-raise the standard
error.

<AutoTypeTable path="../../src/index.ts" name="ResolveContext" />

## Resolver

`Resolver<In, Out, Ctx>` is `(c: ResolveContext<In, Out, Ctx>) => Out` — typed to the
target `Out`, so the escape hatch never widens to `any`.

```ts twoslash
import type { Resolver } from 'bimorph';

// recover an unmapped number to a status, or raise()
type StatusResolver = Resolver<number, 'active' | 'inactive'>;
```

## Miss recovery: default & recover

Decode-side miss recovery is two `Enum` options, not one type. `default` is a plain
domain value (`Out`) substituted for any unmapped wire; `recover` is
`"throw" | Resolver<In, Out, Ctx>`, where `"throw"` is shorthand for a resolver that
re-raises. Setting either widens the decode input; setting neither keeps it the closed
union of declared wires. See [default & recover](/docs/guides/enums/on-miss).

## Reconcile

`Reconcile<Domain>` is the creation-time policy when two primary entries share a
domain value: `"throw"` (default), `"first-wins"`, `"last-wins"`, or a
`(domain, wires) => winner` picker.

```ts twoslash
import type { Reconcile } from 'bimorph';

type StatusReconcile = Reconcile<'active' | 'inactive'>;
```
