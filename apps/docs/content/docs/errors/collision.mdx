title: 'collision'
description: 'Two primary entries shared a domain value, so encode has no single canonical wire to emit — set reconcile or declare an alias.'
---

## What you'll see

A `BimorphError` with `code: "collision"` and the message
`duplicate domain value <value> — set reconcile, or declare one wire as an alias`,
thrown at **creation time**, not on a call.

## Why it happens

Two **primary** entries in an [`Enum`](/docs/guides/enums/enum) share the same domain
value. Decode is fine — both wires decode to that domain value — but encode has to
pick one canonical wire to emit, and two primaries give it no way to choose. Rather
than guess, `Enum` throws when you build it.

## How to fix

Tell `Enum` which wire wins, or that the duplicate is intentional:

- **Set [`reconcile`](/docs/guides/enums/on-collision)** — `"first-wins"`,
  `"last-wins"`, or a `(domain, wires) => winner` picker — to choose the encode
  target. The losing wire still decodes, becoming an implicit alias.
- **Declare the extra spelling as an [alias](/docs/guides/enums/aliases)** instead of
  a second primary. Aliases are decode-only, so they never compete to be the encode
  target — the cleanest fix when the duplicate is a known legacy spelling.
