# Resolver — recovering misses & collisions

By default a decode miss throws and a domain-value collision throws at creation. The
resolver is the escape hatch: `onMiss` recovers unmapped wire values at decode time,
`onCollision` resolves duplicate domain values at creation time. Both are properties of
the *mapping* (creation-time config), never a call-time flag.

## `onMiss` widens the input and recovers

Without recovery the decode input is a **closed union** — an unmapped value is a compile
error. That's the safety guarantee. When you *do* expect unknown values (a newer wire
enum, third-party data), `onMiss` both widens the accepted input and recovers:

```ts twoslash
import { enum_ } from 'bimorph'

// gRPC-style int enum with an UNKNOWN sentinel (D3):
const Status = enum_(
  [[0, 'Unknown'], [1, 'Pending'], [2, 'Shipped']],
  { onMiss: { default: 'Unknown' } },
)

const s = Status.decode(99) // a newer wire int this client has never seen
//    ^?
```

Contrast — with no `onMiss`, that same call is a compile error:

```ts twoslash
// @errors: 2345
import { enum_ } from 'bimorph'

const Status = enum_([[1, 'Pending'], [2, 'Shipped']])

Status.decode(99)
```

## A resolver computes the recovery (and can `raise()`)

The `{ default }` preset desugars to a resolver; you can write one directly. It sees the
failure `reason` and `input`, and `raise()` gives up with the standard error:

```ts twoslash
import { enum_ } from 'bimorph'

const Status = enum_(
  [[1, 'Pending'], [2, 'Shipped'], [0, 'Unknown']],
  {
    // computed resolvers annotate their return so the literal stays in the domain:
    onMiss: (c): 'Pending' | 'Shipped' | 'Unknown' =>
      c.reason === 'miss' ? 'Unknown' : c.raise(),
  },
)

Status.decode(99) // 'Unknown'
```

## A resolver can read runtime `ctx` (and then decode requires it)

When recovery needs information the value doesn't carry — a locale, a region — type the
resolver's `ctx`. The enum becomes contextual: `decode` without `ctx` is a compile error.

```ts twoslash
import { enum_, type ResolveContext } from 'bimorph'

const Currency = enum_(
  [['USD', '$'], ['JPY', '¥']],
  {
    onMiss: (c: ResolveContext<string, '$' | '¥', { locale: string }>): '$' | '¥' =>
      c.ctx.locale === 'ja' ? '¥' : c.raise(),
  },
)

Currency.decode('CNY', { locale: 'ja' })
//    ^?
```

## `onCollision` — intentional duplicate domain values

Two wire values legitimately mean the same thing (legacy HTTP codes → one error). The
loser still decodes (an implicit alias); `first-wins`/`last-wins` bake which wire is
canonical for encode:

```ts twoslash
import { enum_ } from 'bimorph'

const HttpError = enum_(
  [[400, 'ValidationError'], [422, 'ValidationError'], [404, 'NotFound']],
  { onCollision: 'first-wins' },
)

const label = HttpError.decode(422) // legacy 422 still decodes
//    ^?
```
