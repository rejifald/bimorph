# Fidelity tiers

`iso` and `lossy` both keep their throwing doors — the difference is a *promise*, not a
method. `partial` is different: its decode is guesswork, so the throwing `decode` door
is removed at the type level and you must go through `safeDecode`.

## `iso` vs `lossy` — same doors, different promise

```ts twoslash
import { iso, lossy } from 'bimorph'

// clean round-trip both ways
const Bearing = iso<number, number>({
  decode: (compass) => (compass > 180 ? compass - 360 : compass),
  encode: (signed) => (signed < 0 ? signed + 360 : signed),
})
Bearing.decode(350) // -10
Bearing.encode(-10) // 350

// lossy: decode can't recover the exact bytes from a rounded "1.5 GB"
const Bytes = lossy<number, string>({
  decode: (h) => parseFloat(h) * 1024 ** 3,
  encode: (n) => `${(n / 1024 ** 3).toFixed(1)} GB`,
})
Bytes.encode(1_610_612_736)
```

## `partial` removes the throwing decode door

Name parsing has a clean encode (concat) and a guesswork decode. The type reflects it:
`encode` throws as usual, but there is no throwing `decode` — only `safeDecode`.

```ts twoslash
// @errors: 2551
import { partial } from 'bimorph'

const Name = partial<{ first: string; last: string }, string>({
  decode: (full) => {
    const [first, ...rest] = full.split(' ')
    return rest.length
      ? { ok: true, value: { first: first!, last: rest.join(' ') } }
      : { ok: false, error: { path: '', code: 'ambiguous', input: full, message: 'mononym' } }
  },
  encode: (n) => `${n.first} ${n.last}`,
})

Name.safeDecode('Mary Jane Watson')            // ok — the safe door exists
Name.encode({ first: 'Mary', last: 'Watson' }) // ok — encode is the clean direction
Name.decode('Madonna')                          // ✗ no throwing decode on a Partial codec
```
